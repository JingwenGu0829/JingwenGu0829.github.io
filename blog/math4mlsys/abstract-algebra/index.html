Why a little abstract algebra goes a long way in ML systems

Jingwen Gu September 4, 2026 7 min read

Many algorithms in ML systems look unrelated, but at the end of the day they are answering the same question:

Can we replace a complicated computation with a cheap transformation whose structure we can understand?

Abstract algebra, in turn, gives us useful guarantees about how a transformation behaves, and about what happens when many transformations are composed. Two examples make the connection concrete.

01

Cheap permutations in shared-memory swizzling

GPU shared memory is divided into banks that can serve accesses in parallel. When multiple threads in a warp request different words from the same bank, those accesses conflict and may be serialized.

High-performance kernels therefore often swizzle their shared-memory layouts: they apply a small transformation to logical coordinates so that the target access pattern lands on different banks.

Why does XOR appear so often?

If the relevant address bits are vectors in \(\mathbb{F}_2^n\), XOR is simply addition:

\[ x \oplus y = x + y \qquad \text{in } \mathbb{F}_2^n. \]

For any fixed \(r\), the map

\[ c \mapsto r \oplus c \]

is a permutation: if \(r \oplus c_1 = r \oplus c_2\), XORing both sides with \(r\) gives \(c_1 = c_2\). The map is injective, and an injective map on a finite set is a bijection.

So a toy bank map such as

\[ \operatorname{bank}(r,c) = r \oplus c \]

has a useful property: fixing either \(r\) or \(c\) gives a permutation of the bank indices. Its table is therefore a Latin square—every bank index appears exactly once in each row and each column.

For an access pattern that follows one of those rows or columns, lanes are spread across distinct banks. CuTe’s Swizzle<B,M,S> makes the construction explicit by XORing selected address-bit fields. TMA can also apply standard shared-memory swizzles in hardware while moving a tile.

02

Chunked recurrent models: compose transformations, not states

Now consider a recurrent sequence model:

\[ S_t = f_t(S_{t-1}). \]

It looks inherently sequential because computing \(S_t\) requires \(S_{t-1}\). But we can instead look at the transformation applied to the initial state:

\[ S_t = (f_t \circ f_{t-1} \circ \cdots \circ f_1)(S_0). \]

Function composition is associative:

\[ (f_3 \circ f_2) \circ f_1 = f_3 \circ (f_2 \circ f_1). \]

That gives a parallel system permission to group updates into chunks—provided that each composed chunk still has an efficient representation.

The important condition

Associativity makes regrouping legal. It does not make the regrouped computation fast.

DeltaNet is a good example. Its state update can be written schematically as

\[ S_t = S_{t-1}(I - \beta_t k_t k_t^\top) + \beta_t v_t k_t^\top. \]

Each token applies a rank-1 correction to the current state. Naively evaluating these updates one by one loses the sequence-level parallelism that GPUs want.

The hardware-efficient DeltaNet algorithm exploits the structure of the transition matrices. A product of many generalized Householder transformations—with unit-norm keys—

\[ \prod_{t=1}^{C}(I - \beta_t k_t k_t^\top) \]

can be stored in a compact WY-style form rather than materialized as every intermediate state. A chunk of token-wise updates can then be turned into a small number of matrix multiplications—the form modern GPUs execute best.

Kimi Delta Attention carries the same idea further. Its transition has a constrained diagonal-plus-low-rank form,

\[ A_t = D_t - a_t b_t^\top, \]

so it can add fine-grained, per-coordinate decay while retaining a specialized chunkwise algorithm. The lesson is not merely that composition is associative. The transformations must also have a representation that stays compact when they compose.

The shared pattern

Structure is what turns algebra into speed

In the first example, algebra gives us a structured permutation. In the second, it gives us permission to regroup structured state updates.

In both cases, the systems payoff comes from the same pattern: a cheap transformation, a structural guarantee, and a hardware-friendly representation.
